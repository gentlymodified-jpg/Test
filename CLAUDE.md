# Контекст проекта: Obsidian-вольт «Рабочие выходные»

Этот репозиторий используется для построения архитектуры Obsidian-вольта пользователя.
Работа ведётся пошагово, по одной папке/разделу за раз, с обсуждением каждого решения.

## Уже решено (не переспрашивать заново)

- **Название вольта:** «Рабочие выходные» — папка `Рабочие выходные/` в корне репозитория. Это и есть корень вольта — открывать в Obsidian нужно именно эту папку.
- **Синхронизация с телефоном (Android):** через **Google Drive + Autosync/FolderSync**.
  Папка `Рабочие выходные/` кладётся в Google Drive, на телефоне через Autosync синхронизируется в локальную папку, которую Obsidian открывает как vault.
  (Официальный Obsidian Sync обсуждался как более простая платная альтернатива — пользователь выбрал бесплатный вариант.)
- **Структура папки «Мои тексты эссе» (первая папка вольта):**
  - Один файл-эссе = одна **хаб-заметка** прямо в `Мои тексты эссе/` (идея, статус, источники, связанные заметки).
  - Сам текст (черновик/финал) хранится отдельно, в подпапке `Мои тексты эссе/Тексты/`, и связан с хабом через `[[wikilink]]`.
  - Есть индексная заметка `Все эссе.md` со списком ссылок на все хабы.
  - Есть шаблон `Шаблоны/Шаблон - Эссе-хаб.md` для создания новых эссе.
  - Есть пример-заглушка `Пример эссе.md` + `Тексты/Пример эссе — черновик.md` — можно переименовать/удалить, когда появится первое настоящее эссе.

## Текущая структура

```
Рабочие выходные/
├── README.md
├── Мои тексты эссе/
│   ├── Все эссе.md
│   ├── Пример эссе.md
│   └── Тексты/
│       └── Пример эссе — черновик.md
└── Шаблоны/
    └── Шаблон - Эссе-хаб.md
```

## Как продолжать работу

- Пользователь теперь работает через локальный Claude Code (в терминале на своём компьютере), чтобы Claude мог напрямую видеть/менять файлы вольта на диске.
- Двигаться дальше **по одной задаче за раз**: следующая папка/раздел вольта, теги, доп. шаблоны и т.д. — не проектировать весь вольт вперёд одним махом.
- Перед новыми структурными решениями — уточнять у пользователя предпочтения (как в предыдущих шагах), а не додумывать самому.
- Язык общения — русский.
- После значимых изменений — коммитить в git с понятным сообщением (пользователь подтвердил, что это ок для этого репозитория).
